SENA-Lex: Codebase Overview & NLP Architectural Analysis
=========================================================

1. WHAT IS GOING ON IN THE CODE AND WHY?
---------------------------------------------------------
The codebase is a full-stack, offline-first "Defense-Grade" AI platform designed for Computational Law. Rather than sending sensitive legal documents to the cloud (like ChatGPT), SENA-Lex runs entirely locally, ensuring total data privacy. 

The system ingest legal documents (PDF, TXT, DOCX), semantically indexes them, and allows users to query them natively, ask for clause summaries, compare two documents side-by-side, and hunt down punitive clauses/violations. 

Why are we doing this?
Legal professionals demand zero data leakage, and they suffer when LLMs "hallucinate" facts. To solve this, the core objective of the code is to establish an unshakeable connection between the AI's generated answers and the exact source text. It does this by restricting the model to only "RAG" (Retrieval-Augmented Generation) responses, enforcing a robust multi-dimensional confidence engine, and using a knowledge graph to cross-validate entities.

2. THE NLP (NATURAL LANGUAGE PROCESSING) PERSPECTIVE
---------------------------------------------------------
From an NLP point of view, the system utilizes a very mature, enterprise-grade pipeline that transcends simple keyword search:

A. Legal Structuring & Clause Parsing (ingest.py)
Instead of cutting documents arbitrarily (e.g., every 500 words), the system uses Regex + SpaCy (en_core_web_sm) to intelligently map the document’s hierarchy (e.g., "Article 1", "Section II", "Clause 4.1"). Furthermore, the NLP attempts rough intent classification on chunks using semantic heuristics (tagging clauses as Liability, Payment, Termination, etc.).

B. Knowledge Graph & NER (graph_engine.py)
As texts are ingested, SpaCy performs Named Entity Recognition (NER). It identifies organizations, people, locations, dates, and monetary values, mapping them into a NetworkX Knowledge Graph. This creates logical relationships (e.g., "Clause 1.2 MENTIONS Entity [Google]"). Though experimental, this enables "multi-hop" reasoning for complex queries without relying wholly on vector similarity.

C. Advanced Hybrid Retrieval (vector_store.py)
When you query the document, two separate indexing regimes run:
 - Dense Retrieval (Semantic): It calculates sentence embeddings using `nomic-embed-text` running on Ollama, capturing the "meaning" of your query. It stores vectors in FAISS for blazing fast nearest-neighbor lookups. (It even has an intelligent fallback bag-of-words random projection embedder if the local GPU proxy fails).
 - Sparse Retrieval (Exact Keywords): It utilizes rank_bm25 (Okapi) to establish exact text intersections via term frequency-inverse document frequency weighting.
 - Hybrid Merging: Finally, FAISS distance scores (70% weight) and BM25 scores (30%) merge to prevent both hallucinations and zero-recall failures.

D. Generation & Anti-Hallucination (llm.py)
SENA-Lex interfaces with a local Mistral model (`sena-lex-mistral`) served by Ollama. 
 - Query Decomposition: Highly complicated queries are first prompted through the LLM to separate them into 1-3 simpler sub-queries.
 - Verification Trace: After an answer is drafted, a completely separate prompt interrogates the LLM: "Does this answer contain claims, entities, or dates NOT present in the Context?" The answer is strictly flagged as VALID or INVALID based on factual backing.

E. Confidence Engine v2 (confidence_engine.py)
The system calculates a mathematical confidence score built from 5 NLP parameters to prove its accuracy to the lawyer:
 1. Retrieval Relevance (30%): The output of the FAISS+BM25 mechanism.
 2. Answer Faithfulness (25%): The cosine vector similarity between the Answer Text embedding and the Source Document embedding.
 3. Cross-Chunk Agreement (20%): NLP checks if the returned source texts contradict each other (using keyword overlaps and cosine).
 4. Citation Coverage (15%): SpaCy tokenizes sentences and evaluates how many noun phrases (NER variants) physically map to the exact underlying text.
 5. Query Coverage (10%): Checks if all the concepts contained in the user's initial question were actually addressed.

3. FRONTEND / INTERFACE TECH STACK SUMMARY
---------------------------------------------------------
The user interface is built leveraging a modern, high-performance React ecosystem:

- Core Framework: React 19 built on top of Vite (super fast bundling/HMR).
- Styling & Layout: Tailwind CSS v4, allowing for a strictly class-based, beautiful dark mode aesthetic and responsive flex/grid layouts. `clsx` and `tailwind-merge` are utilized for dynamic class merging.
- Animations & Interactivity: Framer Motion governs UI animations, micro-interactions, modal pop-ups, and smooth transitions that give it a "premium" defense-grade feel.
- Icons: Lucide React is utilized for modern, crisp scalable vector graphing icons across the app.
- Networking/API: Axios facilitates HTTP networking across origins (CORS) to directly link frontend components to the Python FastAPI backend backend asynchronously.
